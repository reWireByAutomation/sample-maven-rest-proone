# REST API Testing POC 2.0

This repository is a proof-of-concept automation framework for REST API testing built with:

- Java 11
- Maven
- Cucumber (Gherkin) BDD
- RestAssured for HTTP calls
- TestNG for assertions and test execution
- SLF4J + Logback for structured logging

This README describes the project layout, how to run tests from Maven and from your IDE, how logging and unique run files are produced, and where to find reports and artifacts.

What this implementation does (high level)
- Implements Cucumber feature files and maps each step to a RestAssured call in `RestApiSteps.java`.
- Uses TestNG assertions together with RestAssured validations for clear test failures.
- Produces a single run-level log file per test execution stored in `./logs/test.<timestamp>.log` (project root).
  - When running with Maven, the POM generates a `run.timestamp` and sets `LOG_FILE` for Surefire so Logback uses a unique file for each run.
  - When running from an IDE, the `Hook` class detects that `LOG_FILE` is not set, creates `./logs`, sets `LOG_FILE` to a timestamped name, and updates Logback's file appender at runtime where possible.
- Produces Cucumber reports (HTML/JSON) under `target/cucumber-reports/`.

How logging & unique run file works (details)

### Maven runs (recommended for CI)
   - `pom.xml` (validate phase) generates a `run.timestamp` and writes `run.properties` to the *project root* (not `target/`).
   - During initialization, `properties-maven-plugin` reads `run.properties` so the property `run.timestamp` is available to configure Surefire.
   - Surefire is configured to pass system properties into the test JVM:
     - `LOG_DIR=${project.basedir}/logs`
     - `LOG_FILE=${project.basedir}/logs/test.${run.timestamp}.log`
   - `src/test/resources/logback.xml` uses `${LOG_FILE}` (if present) to write logs to the unique file.

### IDE runs (IntelliJ/Eclipse)
   - The Surefire step is not involved. On the first scenario, `Hook.before` checks if `LOG_FILE` is present.
   - If not, `Hook` creates `./logs`, constructs a timestamped filename `test.<timestamp>.log`, sets `LOG_DIR` and `LOG_FILE` system properties, and (if a FILE appender exists) programmatically updates Logback's FILE appender to use that file.
   - Result: every IDE run also gets a single unique run-level file in `./logs`.

Logback fallback order in `src/test/resources/logback.xml`:
- `${LOG_FILE}` (preferred)
- `${LOG_DIR}/test.log` (fallback)
- `${user.dir}/logs/test.log` (final fallback)

How to run

### 1) Prepare and run from Maven (recommended)

Open a terminal in the repository root and run:

```powershell
# generate run.properties (timestamp) and ensure project-root logs folder exists
mvn validate

# run tests (this will use the generated run.timestamp to create a unique log file)
mvn -DskipTests=false test
```

After the run you will find:
- `./logs/test.<YYYYMMDD_HHMMSS>.log` — the unique run log (project root)
- `target/cucumber-reports/cucumber.html` — HTML report
- `target/cucumber-reports/cucumber.json` — JSON report
- `target/cucumber-reports/cucumber-usage.json` — usage data


### 2) Run from the IDE (IntelliJ/Eclipse)

- Run `src/test/java/org/automation/poc/TestRunner.java` as a TestNG run. The `Hook` will set a timestamped `LOG_FILE` and Logback will write to `./logs/test.<timestamp>.log`.

Useful Maven command lines and run formats

Run the entire test suite (default):
```powershell
mvn -DskipTests=false test
```

Run validate explicitly (generates `run.properties` with timestamp):
```powershell
mvn validate
```

Run tests filtered by Cucumber tag (e.g., `@smoke`):
```powershell
mvn -DskipTests=false -Dcucumber.filter.tags="@smoke" test
```

Common variations / useful combos

- Clean, compile then run tests with a tag filter (ensures a full clean build before test):
```powershell
mvn clean compile test -Dcucumber.filter.tags=@smoke
```

- Clean and run tests (skip maven compile step by letting test phase compile):
```powershell
mvn clean test -Dcucumber.filter.tags="@smoke"
```

- Run test phase with profile and tag filter:
```powershell
mvn -Pci -DskipTests=false -Dcucumber.filter.tags="@smoke" test
```

- Run verify phase (runs integration tests if configured) with tag filter:
```powershell
mvn clean verify -Dcucumber.filter.tags="@smoke"
```

- Run only a single TestNG runner class from Maven (useful to replicate IDE runs):
```powershell
mvn -DskipTests=false -Dtest=org.automation.poc.TestRunner test
```

- Run a single feature file by overriding the Cucumber `features` path:
```powershell
mvn -DskipTests=false -Dcucumber.features="src/test/resources/features/RestApiTesting.feature" test
```

- Run scenarios by name (match the scenario title):
```powershell
mvn -DskipTests=false -Dcucumber.filter.name="Get all posts" test
```

- Exclude a tag (e.g., skip `@wip`):
```powershell
mvn -DskipTests=false -Dcucumber.filter.tags="not @wip" test
```

Run using a TestNG suite XML (if you have a suite file and want Surefire to use it explicitly):
```powershell
mvn -DskipTests=false -Dsurefire.suiteXmlFiles=path/to/your-suite.xml test
```

# Example: run the repository's testng suite file
```powershell
mvn -DskipTests=false -Dsurefire.suiteXmlFiles=src/test/testsuites/testng.xml test
```

# Alternative: clean build then run the TestNG suite via surefire property (useful when you want a full clean compile before tests)
```powershell
mvn clean compile test "-Dsurefire.suiteXmlFiles=src/test/testsuites/testng.xml"
```

Run tests in parallel (TestNG-level parallelization):
- Edit `TestRunner.java` `@DataProvider(parallel = true)` to enable TestNG parallel execution of scenarios.
- Then run:
```powershell
mvn -DskipTests=false test
```


Run Maven with more verbose output (for troubleshooting):
```powershell
mvn -X -DskipTests=false test
```

Notes on Cucumber system properties
- The implementation uses modern Cucumber system properties such as `cucumber.filter.tags`, `cucumber.filter.name`, and `cucumber.features`. These are passed as `-D` properties to Maven and picked up by the Cucumber runner at execution.

Project structure and important files

- `pom.xml` — Maven configuration, dependencies, and build-time creation of `run.properties` and Surefire settings for `LOG_FILE`.
- `src/test/resources/features/RestApiTesting.feature` — example feature file defining Background and scenarios.
- `src/test/java/org/automation/poc/stepdefinitions/RestApiSteps.java` — step definitions. Contains:
  - Methods for GET, POST, PUT, DELETE
  - Response status and body checks
  - JSON field checks that coerce expected values into numbers/booleans when appropriate before asserting
- `src/test/java/org/automation/poc/Hook.java` — Cucumber hooks. Responsibilities:
  - For each scenario `@Before`: reset RestAssured and enable detailed logging for failure debugging
  - For IDE flows: create `./logs` and a timestamped `LOG_FILE` when the system property is missing, and attempt to update the Logback FILE appender so all logs go to the unique file
- `src/test/resources/logback.xml` — Logback config used only in tests (console + file appenders)
- `run.properties` (project root) — generated by `mvn validate`. Contains `run.timestamp` used by Surefire to construct `LOG_FILE`.

Log cleanup (commands and optional Maven profile)

Please NOTE: the project currently preserves previous log files by default. Do NOT run destructive deletion commands unless you explicitly want to remove old logs. Instead, consider archiving older logs (recommended) or running cleanup only after confirmation.

If you must prune old run logs, here are safe options.

Archive (zip) logs older than 30 days (PowerShell):
```powershell
$cutoff = (Get-Date).AddDays(-30)
$old = Get-ChildItem -Path .\logs -Filter "test.*.log" | Where-Object { $_.LastWriteTime -lt $cutoff }
if ($old) {
  $archiveName = "logs-archive-" + (Get-Date -Format yyyyMMdd_HHmmss) + ".zip"
  Compress-Archive -Path $old.FullName -DestinationPath (Join-Path -Path . -ChildPath $archiveName)
  # Optional: remove after confirming archive
  # $old | Remove-Item
}
```

Archive (tar.gz) logs older than 30 days (bash):
```bash
# find files older than 30 days and add them to a tar.gz archive
timestamp=$(date +%Y%m%d_%H%M%S)
find ./logs -type f -name 'test.*.log' -mtime +30 -print0 | xargs -0 tar -czvf logs-archive-${timestamp}.tar.gz
# Optional: remove after confirming archive
# find ./logs -type f -name 'test.*.log' -mtime +30 -delete
```

If you prefer an automated Maven approach, add a profile that performs pruning or archiving. Example (conceptual):

```xml
<profile>
  <id>clean-logs</id>
  <build>
    <plugins>
      <plugin>
        <artifactId>maven-antrun-plugin</artifactId>
        <version>3.1.0</version>
        <executions>
          <execution>
            <id>archive-old-logs</id>
            <phase>validate</phase>
            <goals>
              <goal>run</goal>
            </goals>
            <configuration>
              <target>
                <!-- Conceptual ant script: create archive and optionally remove files -->
              </target>
            </configuration>
          </execution>
        </executions>
      </plugin>
    </plugins>
  </build>
</profile>
```

Run this profile manually (only after you confirm):
```powershell
mvn -Pclean-logs validate
```

(You can improve the above Ant script to delete only files older than N days using the `tstamp` and conditional logic.)

Troubleshooting & tips

- Duplicate step definitions: If you see a DuplicateStepDefinitionException, search your `src/test/java` directory for duplicated Cucumber expressions and remove duplicates.
- Logback duplicate resource: ensure `src/main/resources/logback.xml` is not supplied; this project purposely excludes it so only the test logback is used. If you previously added a main `logback.xml`, remove or rename it.
- If logs are not created for a Maven run:
  - Ensure you run `mvn validate` (or `mvn test`) so the `run.timestamp` gets generated and Surefire receives `LOG_FILE`.
- If logs are not created for IDE runs:
  - Confirm `Hook` runs (Cucumber will call the `@Before` hook). The Hook will create `./logs` and a run-level file if `LOG_FILE` is not set.
